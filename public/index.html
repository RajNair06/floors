02. WHAT IT IS

TEN RULES.
ONE SCORE.
NO OPINION.

Floors takes a floor plan as JSON — rectangular rooms in metres, doors on walls, windows on walls — and runs it through a deterministic checker. Six rules are hard errors (the plan cannot work). Four are warnings (the plan works, but a reviewer might not like it). The output is a pass/fail verdict, a 0–1 score, and a list of violations with suggested fixes.

The checker is the same whether you paste JSON in the browser, call POST /api/score, or connect an MCP client. No accounts, no database, no LLM calls inside the deployed app.

03. METHOD

HOW TO USE IT

01

WRITE A PLAN

Paste JSON, pick a seed, or build one room at a time through the MCP authoring tools. The schema is served from /api/schema so agents and humans share one source of truth.

02

SEE THE VIOLATIONS

The 2D view renders the plan in SVG with coloured overlays on every problem region. The 3D view extrudes rooms at the plan's ceiling height so you can walk around the layout.

03

FIX AND ITERATE

Edit the JSON to address each violation. The plan re-scores in 300 ms. Use the MCP authoring tools to add rooms, connect them, or place openings — all validated on every call.

04

BATCH EVALUATE

Drop up to 50 plans into the Batch tab and get pass rate, mean score, and a per-rule failure breakdown. Useful for comparing prompts, models, or repair-loop iterations.
